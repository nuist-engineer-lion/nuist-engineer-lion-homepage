# 通知目录使用说明

每一条通知是一个独立的 Markdown 文件，放在 `notices/entries/` 目录下。文件一经合入，首页"最新通知"气泡与 [通知中心](/notices/) 会自动更新，无需改动任何其他文件。

## 文件命名

```
notices/entries/YYYY-MM-DD-标题拼音或英文.md
```

例如：`notices/entries/2026-09-10-zhaoxin-qidong.md`

## 文件格式

```markdown
---
title: 通知标题（必填）
date: 2026-09-10
---

显示在列表中的摘要文字。

<!-- more -->

摘要之后、正文其余部分，只在通知详情页显示。
```

## 规则

- `title` 与 `date` 为必填 frontmatter 字段；`date` 使用 `YYYY-MM-DD` 格式。
- 列表按 `date` 倒序排列，首页气泡自动取最新一条。
- 摘要与正文用 `<!-- more -->` 分隔；若不写分隔符，列表中将不显示摘要。
- 删除文件即撤销该通知。

## 自动提交流程（机器人）

通知群中白名单成员发送的纯文本消息，会由 Notify-Bridge-Bot 自动转换为本目录下的通知文件并创建 PR：

- 自动生成的文件名形如 `YYYY-MM-DD-auto-<hash8>.md`，其中 `hash8` 为消息内容 sha256 的前 8 位；相同内容在有待审 PR 时不会重复提交。
- 消息首行作为通知标题，其余部分作为摘要与正文。
- PR 描述中附有来源元数据（来源群、发送者、消息时间、内容哈希）与文件预览，便于审核。
- PR 会自动跑「Validate Notices」检查（文件名与 frontmatter 格式校验）；构建检查由现有 Pages 工作流完成。

### 审核要点

- **合并即发布**：合入 `main` 后站点自动重新部署，首页气泡与通知中心随之更新，结果不回显到群。
- **驳回**：直接关闭 PR 即可；同一内容再次发送会创建新的 PR。
- 标题由机器人取消息首行生成，超长会截断——可直接在 PR 中编辑文件修正标题、摘要或正文后再合并。
- `date` 应为通知发布日期，需与文件名中的日期一致。

### 分支保护建议

在 GitHub 仓库设置中将 `main` 配置为：禁止直接推送、要求至少 1 个 approve、要求检查通过（Validate Notices 与 Pages 构建）后才允许合并。
